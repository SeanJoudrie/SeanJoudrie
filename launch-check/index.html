What it looks for

  • The accounts you need first, like an Apple or Google developer account and a simple website
  • Whether strangers could read your database, and whether secret keys are sitting in your app
  • The legal pages app stores ask for, like a privacy policy and terms of service
  • Store requirements that often catch first-timers, like account deletion, in-app purchase and a login for reviewers
  • Extra rules for sensitive categories such as health, finance and apps for kids

What it doesn't do

Launch Check tells you what to do, why, and where each rule comes from. It doesn't write your code or judge your design, and it isn't a lawyer: it tells you which legal pages you need and how people usually make them, not what yours should say.

Before you paste code

In the real product, checking code means sending it to Launch Check's servers. Then someone other than you has a copy, and no website can promise it will never be breached. A summary gets you the same checklist without that risk.

If you still want to paste code:

  • Keep private code private. If your project is private on GitHub, Replit or anywhere else, use a summary instead.
  • Leave out passwords and keys. They usually sit in a file called .env, or in your builder's Secrets settings (in Replit: Tools → Secrets). Never paste those.
  • Leave out real people's data, like names, emails or scores in sample files.
  • If a key was ever in your code or a chat, make a new one. In that service's dashboard, create a new key, use it, then delete the old one. Deleting it from a file doesn't remove it from your project's history. GitHub explains why (opens in a new tab).
